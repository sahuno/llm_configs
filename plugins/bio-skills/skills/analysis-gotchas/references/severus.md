- **`--min-reference-flank` default 10000 silently filters out all small viral contigs**: For any contig shorter than 2 × 10000 = 20 kb, every position is within 10 kb of both ends, so no breakpoint anywhere on it can satisfy the filter. HTLV-1 (8507 bp), HBV (~3 kb), HHV-8 (~138 kb is on the edge) — all silently return 0 calls. Confirmed 2026-05-01 on HTLV-1 in ATLL ONT data: default-flag run returned 0 HTLV1 entries in `somatic_SVs/severus_somatic.vcf`, `all_SVs/severus_all.vcf`, AND raw `breakpoints_double.csv`. Fix: `--min-reference-flank 100` (effectively disable). Worked: same data, same BAM → 1 high-confidence integration call at chr9:34913979 with 21 supporting reads.
- **`--min-aligned-length` default 7000 drops chimeric reads with short viral side**: Chimeric reads spanning host↔LTR junctions often have <7 kb aligned to the small viral side, especially when the integrated provirus is partial or clipping shortens the viral aligned segment. Compounds the small-contig filter. Set to 500 for viral integration work; default is right for genomic SV calling.
- **Severus emits viral integrations as `SVTYPE=INS`, not `SVTYPE=BND`**: The full proviral sequence is encoded as a multi-kbase literal DNA string in the ALT field. CHROM is the host chromosome. The viral coordinate appears in the `INFO/ALIGNED_POS=<viral_contig>:start-end` field. End coordinate can exceed the viral contig length when the integration spans the linearized contig end and wraps to start (e.g. `HTLV1:7926-16956` on an 8507-bp contig means 7926 → 8507 → wrap → 8449). **Filters keying on CHROM or ALT alone miss every integration call.** Match against `INFO` instead — awk pattern that works: `$8 ~ /ALIGNED_POS=HTLV1:|ALIGNED_POS=EBV:/`.
- **`breakpoints_double.csv` PASS/FAIL is informational, not predictive of VCF output**: A breakpoint shown as `FAIL_LONG` in the CSV (e.g. for our ~9 kb full-length insertion) can still emit as `PASS` in the somatic VCF — Severus re-evaluates at the call stage. Don't filter on the CSV; trust the VCF.
- **`--single-bp` enables hanging breakpoint detection**: Useful for one-sided integration evidence (one LTR-host junction recovered, the other not — defective or truncated proviruses, low-VAF integrations). Off by default. Adds ~10 min to runtime on ONT 30x WGS. Critical for completeness in viral integration work where partial proviruses are common (~50 % of ATLL cases per Matsuoka).
- **Container distribution — pull from Galaxy depot**: Quay.io biocontainer (`docker://quay.io/biocontainers/severus:1.7--pyhdfd78af_0`) hits `too many requests to registry` on apptainer pull (rate limited). Seqera community wave URL (`community.wave.seqera.io/library/severus:1.7--d16d59609ef4ee7d`) — referenced from the nf-core module — requires auth and fails with `unable to retrieve auth token: invalid username/password: authentication required` on anonymous pulls. **Working path**: `wget -O severus_1.7.sif 'https://depot.galaxyproject.org/singularity/severus:1.7--pyhdfd78af_0'` — direct SIF, no auth, ~12 sec, 238 MB.
- **nf-core module exists at version 1.7**: `modules/nf-core/severus` (present, current as of 2026-05-01). Use this for cohort scaling rather than a hand-rolled wrapper. The module's container reference is the Seqera wave URL above; will need substitution for our cluster.
- **Apptainer not in PATH on MSKCC compute nodes**: When running Severus (or any apptainer-wrapped tool) from a Snakemake rule on a SLURM compute node, `apptainer: command not found` at shell exec — the login-node PATH (which has the conda snakemake env's apptainer) does not propagate. Fix: hardcode the absolute path in workflow params (`/home/<user>/miniforge3/envs/snakemake/bin/apptainer`, on NFS-mounted home so it's visible from compute nodes), OR `module load apptainer/1.3.1` at the start of each rule's shell block. Bites Severus first in any pipeline because the canonical invocation is `apptainer exec ... severus ...`.
- **Resource sizing for matched T/N somatic on ONT 30x WGS**: 8 cpu / 32 GB / 1.5 h sufficient. Tumor BAM parse ~32 min for 20M primary reads, normal parse ~21 min for 12M reads, breakpoint detection + clustering + VCF output ~30 min. Peak RSS during parsing ~24 GB. Bump time limit to 2 h for safety margin; bump cpu/mem only if input BAMs >250 GB.
- **`--use-supplementary-tag`**: Required if upstream alignment used `minimap2 -Y` (soft-clipped supplementary alignments). Without it, supplementary alignments may be ignored in breakpoint support. ONT integration callers should always pass this — minimap2 -Y is the standard recipe.
- **Median PASS coverage report**: Severus reports `Median coverage by PASS reads (H1 / H2 / H0)` per sample. H0 = unphased — expected for unphased ONT data, both H1/H2 = 0. With more aggressive filters → more reads pass → higher H0 (Run 1 default flags: 56x; Run 2 relaxed: 63x). Use this as a sanity check that the read-parsing phase ingested the expected fraction of reads.
